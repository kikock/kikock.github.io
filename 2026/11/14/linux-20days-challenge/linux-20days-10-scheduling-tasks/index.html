【Linux 20天实战挑战·Day 10】自动化定时任务：at、Crontab 表达式、自动备份与 Systemd Timers

kikock2026-11-142026-11-14

专栏导读：优秀的系统管理员都是“懒惰”的——他们把每日重复备份、日志清理等枯燥工作全部交给机器定时自动执行。今天我们学习一次性调度 at、最经典的周期调度 cron/crontab，并实战编写一条“每日凌晨 5 点打包备份 /home + 自动清理 7 天前旧备份”的生产级任务链。

1. 学习目标与核心任务

  • 使用 at 调度一次性延迟任务。
  • 掌握 crontab -e / -l / -r 与五段式 Cron 时间表达式。
  • 实战配置两条 root 定时任务：
    1. 每日自动将 /home/ 打包压缩并打上 ISO 日期戳保存到 /var/backups/。
    2. 每日自动检索并删除超过 7 天的历史备份，防止磁盘被撑爆。
  • 了解系统级 /etc/crontab、/etc/cron.{daily,weekly,monthly} 以及现代 systemd timers。

2.4 系统级 Cron 与 Systemd Timers

  • 用户级 Crontab 存储位置：/var/spool/cron/crontabs/（以用户名命名）。
  • **系统级 /etc/crontab**：比普通 crontab 多了一个 user-name 字段，且会自动通过 run-parts 按字母顺序调度 /etc/cron.hourly、/etc/cron.daily、/etc/cron.weekly、/etc/cron.monthly 下的可执行脚本（只需把脚本丢进对应目录即可按周期运行）。
  • **现代替代方案 systemd timers**：现代 Linux 发行版也广泛使用 systemd 定时器，运行 systemctl list-timers 可查看系统当前所有激活的定时器。

3. 动手实战与验证步骤

  1. 使用 at 完成一次 1 分钟后的终端消息推送测试。
  2. 在自己的 crontab -e 中临时添加一条 * * * * * echo "Hello world!" > /dev/pts/0（替换为你的 tty 输出），等待 1~2 分钟确认每分钟触发一次后，用 crontab -r 清理测试任务。
  3. 手动运行 sudo tar -czvf /var/backups/home.$(date -I).tar.gz /home/ 验证备份生成。
  4. 通过 sudo crontab -e 写入每日 05:00 备份与 05:30 清理规则，并用 sudo crontab -l 核对无误。
  5. 运行 ls -l /etc/cron.daily 与 systemctl list-timers 观察系统自带的自动化任务。

4. 进阶延伸与常见避坑

  • Cron 环境变量陷阱：Cron 执行任务时的 $PATH 非常精简（通常只有 /usr/bin:/bin），且不加载用户的 .bashrc。因此脚本里调用自定义程序建议使用绝对路径（可用 which 查询）。
  • 增量备份进阶：全量 tar 在数据量大时耗时耗空间，生产环境常结合 rsync（增量同步）与脚本化保留策略实现更高效的备份。
