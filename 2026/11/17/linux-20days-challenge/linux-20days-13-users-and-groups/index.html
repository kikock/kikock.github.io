【Linux 20天实战挑战·Day 13】多用户治理：用户与组管理、最小权限原则与 visudo 精细授权

kikock2026-11-172026-11-17

专栏导读：在团队协作或代维场景中，绝不能把自己的主管理员账号密码直接交出去。今天我们学习如何创建独立用户与用户组，并通过 visudo 遵循“最小权限原则”，精准授予某位运维助手“仅允许免密重启服务器，但不能乱动其他系统配置”的受限特权。

1. 学习目标与核心任务

  • 创建新用户（adduser）与新用户组（groupadd），理解 /etc/passwd、/etc/group、/etc/shadow 三大纯文本数据库。
  • 将用户加入指定组（usermod -a -G），使用 groups 与 su 验证权限变化。
  • 使用 visudo 安全编辑 /etc/sudoers，为受限用户配置精细化的 NOPASSWD 指令白名单。

2. 核心原理与命令详解

2.1 创建用户与用户组

[!NOTE]
**adduser vs useradd**：在 Ubuntu/Debian 中，adduser 是友好的 Perl 交互式脚本，会自动建家目录、复制骨架文件并设密码；而 useradd 是底层二进制命令，不加参数直接跑不会创建家目录也不设密码。日常管理推荐使用 adduser。

3. 动手实战与验证步骤

  1. 创建用户 helen，分别查看 /etc/passwd、/etc/group 与 sudo cat /etc/shadow 中新增的记录行。
  2. 创建 developers 组并将 fred 加入该组；在把 helen 加入 sudo 组前后，分别用 sudo su helen 测试读取 /var/log/auth.log 的成败。
  3. 使用 sudo visudo 为 fred 配置仅限 /sbin/reboot 的免密权限，保存退出后切换到 fred 验证 sudo ls /root 被拒绝、而 sudo reboot 可正常触发。

4. 进阶延伸与常见避坑

  • 公钥认证环境下的新用户 SSH 登录：如果服务器禁用了密码登录，新建用户后必须为其手动配置 /home/<user>/.ssh/authorized_keys，且严格保证 .ssh 目录权限为 700、authorized_keys 文件权限为 600、属主为该用户本人，否则 SSH 会拒绝登录。
  • 修改 visudo 默认编辑器：设置环境变量 EDITOR=vim 或运行 sudo select-editor，即可让 visudo 默认用 vim 打开。
