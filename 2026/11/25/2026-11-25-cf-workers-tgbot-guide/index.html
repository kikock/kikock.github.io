CF-Workers-TGbot：基于 Cloudflare Workers 的 Telegram Bot API 反代与轻量通知机器人实战

kikock2026-11-252026-11-25

“国内服务器想接入 Telegram 机器人发个告警通知，结果 api.telegram.org 根本连不上？”
“为了跑一个轻量通知 Bot 或者临时反代 API，专门买一台海外 VPS 实在太重、性价比太低？”
“在各种脚本里写消息推送，每次都要硬编码又长又难记的 /bot<Token>，还想知道自己和群组的 chat_id 却懒得抓包？”

在日常服务器运维、CI/CD 告警、青龙面板推送或个人自动化脚本中，Telegram Bot 是最轻便稳定的通知渠道之一。但在部分网络环境下，直连官方 https://api.telegram.org 往往受限，而专门维护一台反代 VPS 又会带来额外的成本与运维负担。

CF-Workers-TGbot 正是为解决这一痛点而生的极简 Serverless 方案。依托 Cloudflare Workers / Pages 的全球边缘网络，仅需一个单文件 _worker.js（零第三方依赖、完全免费额度），即可同时实现 Telegram Bot API 通用反向代理 与 内置 Webhook 轻量通知机器人，开箱即用。

🎯 核心能力与痛点解决

使用痛点 传统方案局限 CF-Workers-TGbot 解决方案
API 连通性受限 需自建海外 VPS + Nginx 反代，有月租与维护成本 边缘节点零成本反代：部署于 Cloudflare Workers/Pages，绑定自定义域名即可稳定转发
多机器人共用繁琐 每个项目单独写反代规则，配置重复 通用 /bot 路径透传：任意机器人只需将 api.telegram.org 替换为你的域名即可
通知脚本调用冗长 每次请求都要拼接长串 BotToken 免 Token 快捷调用：配置 TGTOKEN 环境变量后，直接请求 /sendMessage 自动补全 Token
chat_id 获取麻烦 需要手动调用 getUpdates 接口翻 JSON 内置 /start 与 /id 指令：初始化 Webhook 后在 Telegram 内发送指令秒查 ID 与账号信息

一、工作原理与请求路由机制

整个项目的核心逻辑全部封装在 _worker.js 中，没有复杂的数据库或外部存储依赖。Worker 会根据 是否配置 TGTOKEN、请求 User-Agent 以及 URL 路径 进行智能分流：

具体路由规则如下：

  1. 未配置 TGTOKEN（纯反代模式）
    所有请求原封不动转发至 https://api.telegram.org + 原始路径与查询参数，适合作为公共或团队共用的纯 API 网关。
  2. 已配置 TGTOKEN（反代 + 内置机器人模式）
    • Webhook 接收端：POST /telegram/<TGTOKEN>/webhook，接收 Telegram 推送的更新事件，解析 /start 与 /id 命令并回复 MarkdownV2 格式消息。
    • 浏览器交互分支（User-Agent 包含 mozilla 且无 ? 查询参数、非 /bot 开头）：
      • 访问 /<TGTOKEN>：触发一键初始化，自动向 Telegram 注册 Webhook 与菜单命令（start、id）。
      • 访问其他路径（如首页 /）：自动调用 getMe 获取机器人用户名并代理跳转至 https://t.me/<bot_username>。
    • API 转发分支：
      • 路径包含 /bot：按通用反代处理，直接转发至 https://api.telegram.org/bot...（支持使用其他任意 Bot Token）。
      • 路径不包含 /bot：自动在路径前拼接 /bot<TGTOKEN> 后转发，实现免 Token 调用。

二、从零部署与完整配置步骤

下面介绍 Cloudflare Workers 与 Cloudflare Pages 两种主流部署方式，任选其一即可（推荐 Workers，配置更直观）。

第一步：部署代码

方式 A：Cloudflare Workers 控制台部署（最快捷）

  1. 登录 Cloudflare Dashboard，进入 Workers 和 Pages -> 创建 -> 创建 Worker。
  2. 自定义一个服务名称（例如 tgbot-proxy），点击 部署。
  3. 点击 编辑代码，将仓库中 _worker.js 的全部内容粘贴覆盖进去，点击右上角 部署 保存。

方式 B：Cloudflare Pages 关联 GitHub 部署（适合持续更新）

  1. Fork 仓库 kikock/CF-Workers-TGbot 到自己的 GitHub 账号。
  2. 在 Cloudflare 进入 Workers 和 Pages -> 创建 -> Pages -> 连接到 Git，选择刚刚 Fork 的仓库。
  3. 构建命令留空，输出目录留空（根目录包含 _worker.js 会自动作为高级模式 Worker 运行），直接保存并部署。

方式 C：Wrangler CLI 本地部署

如果你本地已安装 Node.js 和 wrangler，可直接克隆仓库并部署：

仓库中的 wrangler.toml 已预设 keep_vars = true，后续重新 wrangler deploy 时不会覆盖你在控制台里设置的环境变量。

第二步：绑定自定义域名（关键）

由于 Cloudflare 默认分配的 *.workers.dev 与 *.pages.dev 域名在部分网络环境下连通性不佳，强烈建议绑定自己的自定义域名：

  1. 确保你的域名已托管在 Cloudflare DNS 下。
  2. 进入 Worker / Pages 的 设置 -> 域和路由 -> 添加 -> 自定义域。
  3. 输入二级域名（例如 api.tg.example.com），Cloudflare 会自动生成 DNS 解析记录并签发 SSL 证书，等待 1 分钟左右生效。

第三步：配置环境变量 TGTOKEN

  1. 在 @BotFather 中创建一个新机器人（或使用已有机器人），获取 Bot Token（格式类似 6894123456:AAHxxxxxxxxxxxx）。
  2. 进入 Worker / Pages 的 设置 -> 变量和机密 -> 添加。
  3. 填写变量：
    • 类型：文本 / 机密（Secret）均可
    • 变量名称：TGTOKEN（注意全大写，不要写成 TG_TOKEN）
    • 值：填入你的 Bot Token
  4. 点击 保存并部署。

如果你只想做纯 API 反代，不希望别人通过你的域名免 Token 发消息，可以跳过这一步不配置 TGTOKEN。

⚠️ 避坑提醒：为什么不能直接用普通 curl 初始化？
在 _worker.js 中，初始化逻辑位于 userAgent.includes('mozilla') 分支下。如果用不带 User-Agent 的 curl 访问 /<TGTOKEN>，会被当作普通 API 请求转发给 Telegram，从而返回 404 Not Found。因此务必直接用浏览器打开（或使用 curl -A "Mozilla/5.0"）。

三、部署后日常使用指南

1. 在 Telegram 中获取 chat_id 与用户信息

初始化完成后，在 Telegram 中打开你的机器人对话窗口：

  • 发送 **/start**：机器人回复启动提示，并直接给出你的 Telegram ID（即个人私聊 chat_id）。
  • 发送 **/id**：机器人返回完整信息卡片，包含 ID、姓、名、用户名、语言代码 以及 Telegram Premium 会员状态。

四、安全建议与排查清单

安全注意事项

  • 保护好反代域名：一旦配置了 TGTOKEN，任何知道你域名的人都可以直接调用 /sendMessage 以你的机器人名义向任意 chat_id 发送消息。因此切勿将带有 TGTOKEN 配置的域名公开发布到互联网。
  • 妥善保管初始化链接：/<TGTOKEN> 和 /telegram/<TGTOKEN>/webhook 均以 Token 作为路径鉴权依据，不要在公开截图或文档中暴露完整 URL。

常见问题排查

  1. 浏览器访问首页 https://api.tg.example.com/ 跳转到 Telegram 页面？
    这是预期行为。配置 TGTOKEN 后，浏览器直接访问无参数根路径会自动查询机器人信息并代理到 t.me。
  2. 发送 /start 或 /id 机器人没反应？
    • 检查环境变量名是否严格为 TGTOKEN；
    • 重新用浏览器访问一次 https://api.tg.example.com/<你的TGTOKEN>，确认返回两个 "ok": true；
    • 可在 Cloudflare Worker 控制台的 日志 -> 实时日志 中查看是否收到来自 Telegram 的 POST /telegram/.../webhook 请求。
  3. 测试反代是否连通的小技巧：
    在终端执行 curl -I https://api.tg.example.com/，若返回 HTTP/1.1 404 Not Found 且 Content-Type: application/json、Server: cloudflare，说明到 Telegram API 的转发链路已经完全打通。
